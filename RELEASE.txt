H11V release log
================

Newest first. A release is cut per roadmap phase (vA.B -> A.B.0); a post-release
fix on that phase bumps the third number. See specification/SDLC.md.

0.8.0 — 2026-09-14 — the colony retheme
---------------------------------------

  * The world stops looking like Minecraft. Not by recolouring it -- grass, soil,
    bark, leaves and cobble ARE the Minecraft vocabulary, and a recolour cannot
    escape a vocabulary -- but by replacing it. A lander came down on an
    unsurveyed mineral planet: bone regolith, crystal spires instead of forest,
    green-teal meltwater, and the colony's own hardware to build with.
  * 13 blocks, in two halves that must be distinguishable at eight pixels. The
    planet: regolith, fines, lithic, drift, spire, bloom, meltwater, H11 crust.
    The colony: hull, prefab, crate, beacon.
  * The beacon is the point of the second half. Until now the only way to see at
    night was to stand near something H11 had rewritten; a player should be able
    to light their own camp. It emits 14 against the crust's 12, so where the two
    meet the colony's lamp wins.
  * The wield item is the scanner from the references, not a gauntlet. The first
    four hotbar slots are the colony's blocks -- the ones you build with, and the
    ones reachable without cycling.
  * A new art pack (specification/art/colony/), accepted after two revisions, and
    a brief whose section 4.1 is binding: a value ladder with at least 8 L*
    between neighbours, 60 degrees of hue for anything closer. It exists because
    this fiction wants four kinds of pale mineral and the device has no shadows to
    tell them apart. The palette itself was left to the designer; only the rules
    were fixed.
  * The v0 node ids stay resolvable as aliases. Not a migration -- pre-rename
    worlds were already accepted as test fixtures -- but an unresolvable id
    renders as a magenta error cube, and a world that merely looks wrong beats a
    world full of them.
  * Architecture gains two sections it will need before v2: the build catalogue
    (a model emits a plan over authored parts with sockets, never coordinates)
    and mutation as an infection from a focus, whose frontier is a pure function
    of position, cycle and seed so laziness and determinism can coexist. That
    settles the M4 question about catching up missed cycles: they are not
    replayed.

  Two findings the gates could not have produced, both from a screenshot:

  * The growth density was unchanged by the retheme and still wrong. 0.032 suited
    green canopies; the same geometry in magenta covered the world in a solid pink
    field with the terraces, the water and the sense of scale behind it. Now 0.010
    -- about 160 growths, scattered groves, terrain visible between them.
  * test_worldgen.sh had been asserting `trees >= 20` while its own comment said
    this was the DoD's "at least 20 trees in a 128x128 area". It was not: `trees`
    counts sampled columns, one in sixteen, so the gate silently demanded 320. It
    passed for as long as the margin was wide and went red the moment the density
    dropped. The probe now reports `growths`, and the sampling step is a named
    constant rather than a literal in the loop.

0.7.3 — 2026-09-13 — Select cycles the hotbar
---------------------------------------------

  * Select changes the selected block, wrapping round: eight presses return to
    the slot you started on. It took over from L and R when those became the
    turn buttons, and the cycle runs one way only because one button cannot
    sensibly mean two directions.
  * hotbar_previous is now explicitly empty. Its engine default is the B key,
    which is sneak here, so B both crouched and changed blocks; dropping the
    binding is not the same as unbinding it, because the default comes back.
  * The engine's name for this key is KEY_PRINT. Select sends evdev code 99
    (SysRq), and KEY_SNAPSHOT — the name that looks right — is accepted by the
    config parser and never fires.
  * Sway had claimed the key. `bindsym Print exec grim` took it before the game
    saw it, and the evidence was 106 stray screenshots in $HOME, one per press.
    Moved to $mod+Print. Sway does not reload its config when the file changes,
    and `swaymsg -t get_config` reports the config as loaded rather than the file
    on disk, so the two disagreed silently until `swaymsg reload`.

0.7.2 — 2026-09-13 — turning on the shoulder buttons
---------------------------------------------------

  * L and R turn the view. Luanti has no key binding for the camera at all, so
    this is done in a mod; the buttons ride on the `zoom` and `aux1` controls
    because those are the two a mod can observe and nothing else was using them.
  * Both transports had effects of their own and both are neutralised: R no
    longer sprints (the `fast` privilege is actively revoked, since privileges
    live in the world's auth database and survive being dropped from a list), and
    L no longer zooms (the mod pins the field of view while the button is held —
    zoom_fov = fov did not work).
  * dedicated_server_step 0.09 -> 0.02. Both the turn and the zoom correction run
    on that clock: at the default the view moved 11 times a second, which reads as
    stepping, and the zoom flash lasted a full 90 ms. Now 50 Hz for both.

  A brief flash on pressing L remains and is accepted. The client predicts the
  zoom instantly and the server undoes it on its next step; zoom is not a
  registered privilege in 5.10, so there is nothing to revoke, and no client-side
  API exists to suppress the prediction.

0.7.1 — 2026-09-13 — device fixes on v0.7
-----------------------------------------

  * The PocketTerm's gamepad buttons are bound: D-pad moves, A/B jump and sneak,
    X/Y place and dig, L/R cycle the hotbar, Select and Start are inventory and
    chat. They are ordinary keyboard keys — there is no joystick device — and
    because Luanti binds one key per action they replace the desktop keys, so the
    file is device-only and the Mac keeps W/A/S/D.
  * Background music, looping, with /music on|off. Stopped per player on leave,
    or a rejoin layers a second copy over the first forever.
  * The on-screen jump/sneak buttons no longer draw across the hotbar. Their
    touch zones remain — 5.10 can stop drawing a button but cannot move or
    remove one — so the shoulder buttons are now the better way to change slot.

  Fixed underneath: a deploy swapped the config file while the old engine was
  still shutting down, and Luanti writes its settings back as it exits. The new
  config was being silently overwritten by the dying process's memory, comments
  intact, so it looked like it had worked. The deploy now waits for the process
  to be gone.

0.7.0 — 2026-09-13 — v0.7 The measurement session, and v0 complete
------------------------------------------------------------------

The device answered the questions v0 existed to ask.

  * Low and mid hold 30 fps with a drawtime of 2-3 ms against a 33 ms budget —
    the V3D is barely working and there is real headroom for v1 and v2. High
    cannot reach 60, and the engine cuts its view range from 100 to 60 trying to.
    mid is the default.
  * 32x32 textures read at 3.5 inches. Confirmed the hard way: 16x16 was built,
    installed, looked at and reverted, which also retired two plausible arguments
    for it — "drawn in 2-pixel clusters" (measured: 44%) and "shimmers less"
    (measured: no difference).
  * The bright palette holds at night rather than going grey, the H11 glyph
    reads, and touch digging and placing work.

  Three defects that only a person holding the device could find:

  The game granted no privileges, so /time refused and the touch menu's own
  Fly/Fast/Noclip buttons were dead. It looked finished while three of its
  controls did nothing.

  Night was unplayable, and 5.10 has no brightness lever — no light_curve_*
  family, and display_gamma measurably does nothing. Light in this engine comes
  from blocks, so the H11 crust became the light at 12 of 14. ART.md already said
  H11 leaves a faint cyan-to-lilac glow on what it has touched; from v1 the
  mutation front will light the world as it spreads.

  The engine's dialogs overflowed a 640x480 panel in two ways needing two fixes:
  font_size for labels overlapping inside their cells, gui_scaling for a dialog
  simply wider than the screen.

  Also: the game is in the Sway menu, tree density is a setting so the world's
  shape can be judged from outside a forest, and a measurement protocol exists
  that sets up identical conditions and captures the evidence without pretending
  to read a frame rate off its own screenshot.

0.6.0 — 2026-09-13 — v0.6 Device profiles and scripts
----------------------------------------------------

The game runs on the PocketTerm35. One command deploys it, one stops it, and the
Mac runs it the same way.

  * Three graphics profiles assembled from a shared base, so a profile switch is
    a redeploy rather than an edit on the device.
  * tools/run_local.sh — the Mac, same config, same 640x480.
  * The deploy starts the game over ssh and it outlives the session.

  Getting there disproved most of what the specification assumed:

  The device's Luanti is the legacy Irrlicht X11 build — libX11, no SDL, no EGL,
  no GLESv2. It contains the strings "ogles2" and "opengl3" and rejects both,
  then dies asking for a DISPLAY. Only opengl is compiled in; the path is
  GLX -> XWayland -> V3D. Still hardware (direct rendering: Yes), but not the
  path the specification described.

  The GPU preflight was verifying a path the game does not take. It asked EGL,
  which answered V3D correctly and said nothing about the renderer the game would
  get. A check that verifies the wrong path is not weaker, it is false.

  --gameid list prints to stderr on 5.10 and stdout on 5.17, so v0.1's
  visibility guard blocked a deploy that would have worked. A guard producing
  false positives is worse than no guard, because it is believed.

  Also: the engine will not create a world from the command line; its log appends
  across runs, so the renderer check would have reported a stale line forever;
  and --stop returned on signal delivery rather than process exit.

0.5.0 — 2026-09-13 — v0.4 The asset pack + v0.5 The player layer
----------------------------------------------------------------

The game becomes playable and stops being untextured.

  * The designed pack installed into the game tree, metadata stripped (146 KiB
    of content-credential chunks that would have crossed the network on every
    deploy). check_assets.py now runs against the game, where leftover metadata
    is a hard failure rather than a tolerated note.
  * check_assets.py gained the half a delivery audit cannot see: the pack's
    filenames and the code's references must agree. A mistyped texture in a
    NODES row is not an engine error — it is a placeholder that looks like an art
    problem and is a typo.
  * player.lua — the hand covers all four dig groups the NODES table uses (miss
    one and that block is silently undiggable), a searched spawn that finds turf
    above the water line with headroom rather than the engine's static one, a
    starting inventory of everything placeable, and a hotbar-and-crosshair HUD.
  * Hotbar width verified: 627 px of 640 at hud_scaling 1.4, a 13 px margin.

  v0.4 and v0.5 are released together: the asset work was two small issues on an
  already-delivered pack, and neither phase is meaningful to play without the
  other.

0.3.0 — 2026-09-13 — v0.3 Water and trees
-----------------------------------------

The island reads as a place: water that flows, trees that stand.

  * water_flowing completes the liquid pair, cross-referenced both ways. Without
    it the first shoreline the player digs spawns unknown-node checkerboards.
  * Trees as a decoration schematic — placed once with the chunk by the mapgen
    thread, costing nothing per tick. No leafdecay: a per-tick ABM over every
    leaf is not what v0 should be measuring.
  * Gate: elevation_range=19, turf 92%, water=70, trees=46.

  Two things v0.2 had wrong, found while giving the water somewhere to be:

  set_mapgen_setting(..., false) means NEVER, not "unless already set" — the
  engine writes its defaults into map_meta at world creation, before mods load.
  v0.2's terrain tuning was inert, and the elevation range it cited as proof was
  stock v7 noise.

  v7's height is a blend of two noises through a third, not one noise, so tuning
  terrain_base alone moves almost nothing. The blend is now pinned and
  terrain_base is the single dial.

  And one the trees found: the gate called the first solid node from the sky "the
  surface", which once trees existed was a canopy. Ground and canopy are now
  distinct, with the definition written where it is computed.

0.2.1 — 2026-09-13 — post-release fix on v0.2
--------------------------------------------

  * test_worldgen.sh asserted the DoD's elevation threshold at any --area, so
    iterating with a smaller sample produced a red gate that meant "you passed a
    smaller area", not "the world regressed". The threshold describes the 128x128
    map; below that area it is now reported rather than asserted. A gate that
    cries wolf is how red gates start being skimmed past.

0.2.0 — 2026-09-13 — v0.2 Blocks and terrain
--------------------------------------------

The world stops being empty: our own blocks, our own terrain, and the headless
gate every later phase is held to.

  * nodes.lua — eight blocks as eight rows and one loop, because v1's mutation
    rules are rows addressing these same node ids. Required keys asserted at load.
    Turf's tiles are a three-element list: Luanti's shorthand fill-in would
    otherwise draw the green fringe on the block's underside.
  * mapgen.lua — the three aliases v7 actually reads, and one technical biome.
    The v6 aliases' absence is the load-bearing part: register them under v7 and
    the world is bare stone, with no error to explain it.
  * tools/test_worldgen.sh — a dedicated server, a force-emerged area, a
    VoxelManip scan, one parseable line, guaranteed shutdown. Kernel-assigned
    port and cleanup on every exit path, after v0.1 lost an afternoon to a
    leftover server holding 30000.
  * The gate proves the DoD: elevation_range=19 against a required 8, turf on 99%
    of 1024 sampled columns, no engine errors. Verified red by breaking the biome
    on purpose — a gate never seen to fail is not known to work.

  Fixed before the tag: water_source was registered with drawtype
  "liquidsource", which is not a Luanti drawtype. The engine falls back to a
  normal cube, so water would have looked like solid teal stone while behaving
  like water. ARCHITECTURE.md already said "liquid".


0.1.0 — 2026-09-13 — v0.1 Toolchain and skeleton
------------------------------------------------

The engine runs on both machines, the device renders on its GPU, and H11V exists
as a game Luanti will load.

  * Luanti 5.17.0 on the Mac, 5.10.0 on the PocketTerm35. The seven-version skew
    is deliberate: Debian's package uses the system Mesa the device ships, where
    a Flatpak would inject its own into the measurement v0 exists to take. The
    mod API surface must therefore stay inside 5.10's.
  * GPU preflight GREEN: V3D 7.1.7.0 via EGL, no llvmpipe fallback. Any frame
    rate measured without this line green is void. tools/gpu_preflight.sh makes
    the check repeatable.
  * games/h11v with game.conf and an empty h11_world whose init.lua documents the
    load order v0.2 and v0.5 will fill in. Verified headless: the server listens
    for gameid h11v and creates a world.
  * tools/luanti_path.sh resolves the headless server across both platforms —
    macOS ships no luantiserver, only a --server flag on a bundled binary.
  * docs/decisions.md seeded with the decisions closed during specification plus
    everything v0.1 learned.
  * Four specification corrections forced by what the engine actually does, and
    four code-review findings fixed before release.

  Known and owned: an empty game logs three "Mapgen alias ... is invalid!" errors
  because the engine demands those aliases before any node exists to satisfy
  them. v0.2's DoD closes them.
