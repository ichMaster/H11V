## Detailed Results

### H11V-001 — Install Luanti on the Mac and pin the version
**Status:** completed · **Commit:** `06f2c38`

Luanti 5.17.0 via the Homebrew cask. Two findings, both of which would have cost v0.2 an afternoon:

- **The macOS cask ships no `luantiserver`.** One binary inside an `.app`, not on `PATH`, with
  dedicated-server mode behind `--server`. Debian ships a separate binary. Added
  `tools/luanti_path.sh` to resolve both; corrected `ARCHITECTURE.md`, `SDLC.md` and `CLAUDE.md`,
  which had all claimed the Debian name unconditionally.
- **5.17.0 ≥ 5.11**, so mandatory shaders apply on the Mac and `enable_shaders` is gone.

### H11V-002 — Install Luanti on the PocketTerm35 and pass the GPU preflight
**Status:** completed · **Commit:** `419ba67`

Luanti 5.10.0 from Debian trixie. **Preflight PASS: `V3D 7.1.7.0`, `LIBGL_ALWAYS_SOFTWARE` unset.**
Added `tools/gpu_preflight.sh` so the check is repeatable over ssh.

- **Version skew accepted deliberately** (device 5.10 vs Mac 5.17): a Flatpak would inject its own
  Wayland/Mesa plumbing into the measurement v0 exists to take. Consequence recorded as a constraint:
  the mod API surface must stay inside 5.10's.
- **`luanti-server` enabled a systemd unit** that would have run a dedicated server across all four
  cores in the background, taxing every v0.7 figure. Disabled and stopped.
- **`eglinfo`, not `glxinfo`** is the correct probe — Luanti renders through EGL on Wayland and
  `glxinfo` reports nothing over a session with no X display.
- 5.10.0 is not 5.8, so the known aarch64 touch regression does not apply.

### H11V-003 — Game skeleton
**Status:** completed · **Commit:** `1fad5ee`

`game.conf` + `h11_world` with an `init.lua` that registers nothing and documents the load order.
Verified headless: `Server for gameid="h11v" listening`, the mod logs its load, a world is created
carrying `gameid = h11v`. `check_lua.sh` became a real gate ("1 file(s) parse").

- `name` in `game.conf` is deprecated in favour of `title`; fixed.
- **The engine demands the three mapgen aliases before any node exists to satisfy them** — empirical
  confirmation of exactly the alias set `ARCHITECTURE.md` names for v7.
- **A portability bug in `luanti_path.sh` from H11V-001 was caught and fixed here:** zsh does not
  word-split an unquoted parameter, so a two-word `$LUANTI_SERVER` became one nonsensical filename.
  Replaced with a `luanti_server()` function; verified under both bash and zsh.

## Architecture impact

Four corrections landed in the specification during this phase. Each is a document that was wrong
before the code proved it, and each rode in the same commit as its discovery:

1. **`ARCHITECTURE.md` §Engine primitives** — "Headless tests | `luantiserver`" was true only on
   Debian. Now names both platforms and points at `tools/luanti_path.sh`. Mirrored in `SDLC.md` and
   `CLAUDE.md`.
2. **`ARCHITECTURE.md` §Acceptance / §Headless test mechanics** — the gate's description now says "a
   headless server" and mentions resolving the invocation.
3. **`ROADMAP.md` §v0.2 DoD** — amended to state that registering the aliases closes the three
   `Mapgen alias ... is invalid!` errors v0.1 structurally leaves behind. The hand-off is now written
   down instead of assumed.
4. **`ARCHITECTURE.md` §Components / `VISION.md` §Still open** — the v3 brain host is named and
   probed (`ich-picobox`, no discrete GPU), and the Mac is ruled out as a host with the reason.

No architecture *seam* changed: the `NODES` table, the mutation rule table and `Perception → Intent`
are untouched, as v0.1 registers nothing.

## Deviation from the DoD, stated plainly

The v0.1 DoD says the game "creates a world without errors". It creates a world, and all *warnings*
are cleared — but three `Mapgen alias ... is invalid!` **errors** remain, and they cannot be cleared
at v0.1: Luanti requires those aliases to point at real nodes, and the first node is a v0.2
deliverable. This is structural, not a defect. It is recorded here, and v0.2's DoD now names closing
them as part of its own acceptance.

## Also landed in this phase

Two pieces of housekeeping rode along rather than being deferred:

- **Three stale rules removed from the skills.** `execute-issues`, `generate-issues` and
  `review-and-fix-issues` still carried the SDLC kit's origin-project vocabulary (server seats,
  per-connection tokens, a wire event/action protocol). Retargeted to this project's real seams.
- **One `codegen` schema fix.** `issue.validate.end` *required* `pytest` and `mypy` data keys — gates
  this project has no equivalent of — so every validate event was being silently dropped. They are
  now optional; gate results ride in a `gates` object. 293 tests still pass.

**v0.2 — Blocks and terrain** is unblocked, and inherits three concrete constraints from this phase:

- The `NODES` table and `mapgen.lua` must work on **Luanti 5.10**, not 5.17.
- `test_worldgen.sh` must call `luanti_server()` from `tools/luanti_path.sh`, never a hardcoded

  server holding 30000, and the next run fails with a bind error that looks nothing like its cause.
