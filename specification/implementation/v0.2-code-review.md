## Findings

### 1. 🔴 HIGH — a drawtype that does not exist

**`nodes.lua`**, the `water_source` row: `drawtype = "liquidsource"`. Luanti has **no such
drawtype**. Grepping the engine's own `builtin/` finds `flowingliquid`, `normal`, `airlike`,
`nodebox` and the rest — and no `liquidsource`. The valid name for a source is `"liquid"`, which is
exactly what [ARCHITECTURE.md](../ARCHITECTURE.md) §Three details the engine is strict about already
specifies. The code contradicted its own pinned contract.

**Failure scenario:** an unknown drawtype is not an error. The engine falls back to `normal`, so
water renders as a **solid opaque teal cube**. It is still non-walkable and non-diggable, so it
behaves like water and looks like stone — and nothing in any log says why. The v0.2 gate could not
catch it because this terrain generates above the water line (`water=0`), so the defect would have
surfaced either in v0.3's water assertions or, worse, as a visual oddity in v0.5 that reads like an
art problem rather than a one-word typo.

This is precisely the class of silent engine strictness ARCHITECTURE exists to enumerate, which is
the irony worth recording: the document was right and the code did not follow it.

**Fix:** `drawtype = "liquid"`, with the reason in a comment so the next person does not re-guess.

### 2. 🟠 MEDIUM — the gate accepts nonsense as success

**`tools/test_worldgen.sh`**, `assert_min`:

```bash
if [ "$2" -lt "$3" ] 2>/dev/null; then FAIL else ok fi
```

`[ nil -lt 8 ]` is not false — it is an **error**, exit status 2, with the message swallowed by
`2>/dev/null`. A bare `if` reads any non-zero status as "take the else branch", so the gate prints
`ok elevation_range=nil (>= 8)` and passes. Verified directly.

**Failure scenario:** the probe reports `surface_min=nil` whenever it samples nothing — which is
exactly the empty-world case the gate exists to catch. `status=empty` happens to catch it today, so
the two checks were accidentally covering for each other; remove or change either and a wholly empty
world passes the gate green.

**Fix:** reject a non-numeric value explicitly, before the comparison.

### 3. 🟡 LOW — an unused parameter

`surface_at(vm, area, data, x, z)` never touches `vm`; it reads through `area` and `data`. Removed —
in a function whose whole job is a tight loop, a parameter that does nothing invites the reader to
look for the thing it must be doing.

### 4. 🟡 LOW — a field contradicting its own config

The biome set `node_dungeon` while `mg_flags` disables dungeons, under a comment about shore sand
that described neither. Removed; the comment was left-over from a line that had already changed.

## What's solid

- **The `NODES` required-key assertion earns itself immediately.** It is the kind of check that looks
  like ceremony until a row is added in a hurry.
- **The gate prints what it measured on every line, pass or fail.** Finding #2 was found *because*
  the failure output is legible enough to reason about.
- **`mapgen.lua` documents the absent v6 aliases.** The load-bearing part of that file is a thing it
  does not do, and a comment is the only way to express that.
- **The emerge-callback wait is right.** Three byte-identical consecutive runs is not luck.
- **Deliberately breaking the biome to see the gate go red** (H11V-008) is what gave the phase a gate
  known to work rather than assumed to.

## Fixes applied

All four landed in one commit. Verification after the change:

- `tools/test_worldgen.sh` — **PASS**: `elevation_range=9 (>= 8)`, `surface_top=h11_world:turf`,
  `surface_top_pct=100 (>= 80)`, no engine errors.
- `assert_min` regression, checked directly: `nil` → **FAIL (not a number)**, `19` → ok, `3` → FAIL.
  The nonsense case now fails, which it did not before.
- `tools/check_lua.sh` — green, 4 files.
- `tools/check_assets.py --pack` — green, 25 files.

**Regression check for #1:** the real one arrives in v0.3, whose DoD asserts water is present and
flows. That is the phase where a mis-drawn liquid becomes observable, and its assertions now have a
correctly-typed node to assert against. Noted in the next-steps below so it is not forgotten.

### Architecture impact

**None.** Finding #1 moved the code *toward* the documented contract rather than away from it —
`ARCHITECTURE.md` already said `drawtype = "liquid"` and needed no change. The `NODES` row shape,
the mutation rule table and `Perception → Intent` are untouched.

Worth recording for the next phase: **`ARCHITECTURE.md`'s list of engine strictnesses was correct and
was not followed.** The document is doing its job; the gap was in reading it. v0.3 touches the same
liquid plumbing, so its issues should quote the contract rather than paraphrase it.

### 5. 🟠 MEDIUM — a threshold applied outside the map it describes *(found after the 0.2.0 tag)*

Running `tools/test_worldgen.sh --area=48` — the documented way to iterate quickly — failed with
`FAIL elevation_range=5 (need >= 8)`. The terrain is fine: a 48x48 sample of the same map honestly
ranges 5 blocks, while the full 128x128 ranges 19. The DoD's "at least 8 blocks" describes **the
map**, not a density, so asserting it against a fraction of the map measures nothing.

**Failure scenario:** the gate exists to be trusted. A red result that means "you passed a smaller
area" and not "the world regressed" is how a team learns to skim past red gates — the single most
expensive habit a project can acquire. It was found here by running the gate at an area that had not
been used since before the assertions landed.

**Fix:** assert `elevation_range` only at the contract area (128); below it, report the measurement
as informational. Composition assertions (`surface_top`, `surface_top_pct`) are densities and apply
at every size, so they stayed unconditional.

Shipped as **0.2.1**, a post-release fix on the phase, which is exactly what the third version
number is for.
