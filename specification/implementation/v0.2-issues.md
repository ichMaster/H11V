# v0.2 — GitHub Issues

Issues for phase **v0.2 — Blocks and terrain** (version **v0 — The device: one player, one island, at
a measured frame rate**), derived from the per-phase Tasks in [ROADMAP.md](../ROADMAP.md) (§v0.2) and
the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md) (§Components, §Three details the engine is
strict about, §Acceptance and testing). IDs continue from the previous phase (H11V-004 →
**H11V-005…008**).

This is the phase where the game stops being a shell. It lands the block catalogue as a data table —
the structure every later mechanic addresses, since v1's mutation rules are rows over these same node
ids — points the stock generator at those blocks, and builds the headless gate that every issue from
here on must pass.

**Reconciled against the real implementation (Step 0.5).** v0.1 shipped and its execution report and
code review carry four constraints this phase inherits. They are not in the roadmap text and each one
would otherwise be rediscovered the hard way:

- **The device runs Luanti 5.10, the Mac 5.17.** The API surface used here must exist in 5.10, because
  the device is where the game has to run. `docs/decisions.md`, 2026-09-13.
- **`test_worldgen.sh` must call `luanti_server()` from `tools/luanti_path.sh`**, never a hardcoded
  binary name — macOS ships no `luantiserver`, and the resolver must be sourced as
  `. tools/luanti_path.sh || true` so `set -e` does not kill the caller before its own message.
- **A killed server keeps port 30000.** Observed during v0.1: the next run then fails with a bind
  error that looks nothing like its cause. The gate must bind a free port and shut down under every
  exit path.
- **The three mapgen-alias errors are this phase's to close.** v0.1 structurally could not clear them;
  the DoD now names them.

One thing this phase must *not* do: register water's flowing partner or trees. Those are v0.3, and
`NODES` is deliberately built to be extended by a row.

## v0.2 — Blocks and terrain

### H11V-005 — `nodes.lua`: the `NODES` table and the registration loop

**Description:**
The block catalogue, as data. Touches `games/h11v/mods/h11_world/`. One table, `NODES`, and a loop
that calls `core.register_node` for each row — because from v1 the mutation rules are rows of the
form `rule → block transformation → condition` over exactly these node ids, and a catalogue expressed
as a hundred separate calls cannot be addressed that way. This issue defines the table's **shape**,
which is a seam: [ARCHITECTURE.md](../ARCHITECTURE.md) names the `NODES` table shape as a contract.

**What needs to be done:**
- `NODES` covering the eight v0.2 block types: `dirt`, `turf`, `stone`, `sand`, `trunk`, `leaves`,
  `crust`, and `water_source`. The ninth registered node, `water_flowing`, is v0.3's row.
- Each row carries: the node id suffix, `description`, `tiles`, dig `groups`, and optional
  `drawtype` / `light_source` / liquid fields. Rows are data; the loop holds the only engine call.
- **Tile order is `{top, bottom, right, left, back, front}` with shorthand fill-in** — so turf needs a
  **triple**, `{h11_turf_top.png, h11_dirt.png, h11_turf_side.png}`, or its green-fringed side
  texture lands on the block's underside. Trunk takes a pair. This is one of the three engine
  strictnesses that fail silently rather than loudly.
- Leaves use `drawtype = "allfaces_optional"` so the engine may simplify them on the low profile.
- The crust emits a little light (`light_source`) for its glyph glow.
- Textures are referenced by the exact filenames [ART.md](../ART.md) §5.1 fixes. The pack is not
  installed until v0.4, so the engine will report missing textures — that is expected and is not this
  issue's failure.
- Wire `dofile(modpath .. "/nodes.lua")` into `init.lua`, uncommenting the first of the three lines
  v0.1 left documented there.
- Lua is `local` by default: no globals beyond the one table the mod exports.

**Dependencies:** None

**Expected result:**
Eight nodes registered from a single data table, and a headless server start that logs no node
registration errors.

**Acceptance criteria:**
- [ ] Eight nodes register; `core.registered_nodes` contains each `h11_world:*` id.
- [ ] **Contract test:** the `NODES` table shape is pinned — a row's required keys are asserted, so a
      later phase adding a row cannot silently omit one. `ARCHITECTURE.md` updated in the same commit
      if the shape differs at all from what it describes.
- [ ] Turf's tiles are a three-element list with `h11_dirt.png` in the middle (the bottom face).
- [ ] **Gate:** `tools/check_lua.sh` green.
- [ ] Ties to the v0.2 DoD: the blocks the biome and the assertions need exist.

### H11V-006 — `tools/test_worldgen.sh`: the headless world gate

**Description:**
The acceptance gate every issue from here on runs. Touches `tools/`. It starts a headless server with
the game, force-emerges an area, scans it with a VoxelManip, prints one parseable result line, and
shuts the server down. The scanning mod lives under `tools/` and is **never shipped inside the
game** — the game itself contains no test code.

**What needs to be done:**
- A throwaway world directory per run, removed afterwards, so runs cannot contaminate each other.
- A test-only world mod under `tools/` that on server start emerges the area, scans it, prints one
  line of the form `H11V-WORLDGEN <key>=<value> ...`, then calls `core.request_shutdown()`.
- The script sources `tools/luanti_path.sh` as `. tools/luanti_path.sh || true`, checks
  `LUANTI_MISSING`, and calls `luanti_server()` — never a hardcoded binary name (macOS has no
  `luantiserver`).
- **Bind a free port, and always shut down.** A killed server keeps 30000 and the next run fails with
  a bind error that reads like a different bug; trap the exit paths so the server and the temporary
  world are cleaned up whether the script succeeds, fails or is interrupted.
- A timeout, so a server that never reaches the scan fails the gate instead of hanging the pipeline.
- Exit 0 on all assertions passing, 1 otherwise, with the parsed values printed either way.
- This issue establishes the harness and asserts only that the world generated at all; H11V-008 adds
  the terrain assertions.

**Dependencies:** H11V-005

**Expected result:**
`tools/test_worldgen.sh` runs headless on the Mac, prints its result line, exits 0, and leaves no
server process and no world directory behind.

**Acceptance criteria:**
- [ ] Exits 0 on a good world, 1 on a bad one, with the result line visible in both cases.
- [ ] Leaves no stray process (`pgrep` clean afterwards) and no temporary world directory.
- [ ] Two consecutive runs both pass — the port and cleanup regression from v0.1.
- [ ] Uses `luanti_server()`; no binary name appears in the script.
- [ ] **Gate:** it *is* the gate; `check_lua.sh` green on the test mod's Lua.

### H11V-007 — `mapgen.lua`: aliases, surface biome and mapgen parameters

**Description:**
Point the stock generator at our blocks. Touches `games/h11v/mods/h11_world/`. This is the issue that
makes the world ours rather than bare stone, and it contains the second of the engine's silent
strictnesses.

**What needs to be done:**
- Register the three aliases v7 actually reads: `mapgen_stone`, `mapgen_water_source`,
  `mapgen_river_water_source`. These are the exact three v0.1 saw the engine complain about; the v6
  aliases (`mapgen_dirt`, `mapgen_dirt_with_grass`, `mapgen_sand`) are **ignored by v7** and
  registering them instead yields a world of bare stone and water.
- **One `core.register_biome`** covering the whole heat/humidity range: `node_top = h11_world:turf`,
  `depth_top = 1`, `node_filler = h11_world:dirt`, `depth_filler = 2`,
  `node_riverbed = h11_world:sand`. Surface layers come from biome definitions, not from aliases.
  This is a *technical* registration, not a gameplay biome — the three H11V biomes are v1.1.
- Mapgen selection and parameters for a pocket-world feel: modest height amplitude, a sensible water
  level, caves off in v0.
- Wire `dofile(modpath .. "/mapgen.lua")` into `init.lua`.
- Everything used must exist in **Luanti 5.10**, not just 5.17.

**Dependencies:** H11V-005

**Expected result:**
A generated world has turf on its surface, dirt beneath it, stone below that — and the engine log is
free of the three mapgen-alias errors.

**Acceptance criteria:**
- [ ] The three `Mapgen alias ... is invalid!` errors are gone from a headless start — the v0.2 DoD's
      "engine log is clean" clause.
- [ ] A generated world's surface node is `h11_world:turf`, not `h11_world:stone` or `air`.
- [ ] Only the three v7 aliases are registered; the v6 trio is absent, with a comment saying why.
- [ ] **Gate:** `tools/test_worldgen.sh` green; `check_lua.sh` green.

### H11V-008 — Assert the terrain: elevation range and turf on top

**Description:**
Turn the harness into the phase's real gate. Touches `tools/`. The DoD says the world must have "a
horizon with elevation rather than a slab" and turf on top; this issue makes both machine-checkable,
so no later phase can flatten the world or break the biome without a red gate.

**What needs to be done:**
- Extend the scanning mod to compute, over the emerged area: the **surface elevation range**
  (highest minus lowest surface y) and the **composition of the surface layer** (which node ids
  appear on top, and in what proportion).
- Assert `elevation_range >= 8` and that the dominant surface node is `h11_world:turf`.
- Report the measured values on the result line whether it passes or fails — a gate that says only
  "FAIL" costs a debugging session that a gate printing `elevation_range=3` does not.
- Emerging is asynchronous: the scan must wait for the area to be fully emerged rather than sampling
  a half-generated map, or the gate will be flaky — which is worse than absent.

**Dependencies:** H11V-006, H11V-007

**Expected result:**
`tools/test_worldgen.sh` proves the v0.2 DoD, and would fail if the biome or the terrain regressed.

**Acceptance criteria:**
- [ ] Asserts `elevation_range >= 8` and dominant surface node `h11_world:turf`.
- [ ] Deliberately breaking the biome (pointing `node_top` at stone) turns the gate red — verified
      once, then reverted. A gate never seen to fail is not known to work.
- [ ] Not flaky: three consecutive runs agree.
- [ ] **Gate:** `tools/test_worldgen.sh` green; ties to the v0.2 DoD in full.

## v0.2 scope notes

**Total effort:** M+M+M+S — the bulk is `test_worldgen.sh`, which is infrastructure every later phase
leans on rather than one phase's cost.
**Critical path:** H11V-005 → H11V-007 → H11V-008, with H11V-006 buildable alongside 007.
**Phase DoD (roadmap §v0.2):** a generated world has turf on top and dirt under it — not bare stone —
with a surface elevation range of at least 8 blocks, and the engine log is clean of the three mapgen
alias errors.
**Contracts pinned this phase:** the **`NODES` table shape** (H11V-005) — the first real seam in the
project, and the one v1's mutation rules address. Its contract test and any `ARCHITECTURE.md`
correction land in that same issue.
**Device note:** no frame-rate claim is made in this phase; the device gate is not exercised. The API
surface must nonetheless stay within **Luanti 5.10**, which is what the device runs. **No paid APIs**
anywhere in the acceptance path.
