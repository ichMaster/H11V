# H11V — Full code, design & visualization review (at v0.8.0)

**Date:** 2026-09-14 · **Scope:** the repository at tag `0.8.0` (commit `4130b54`) — game Lua, shell tooling, Python gates, all specification documents, the installed asset pack, and the on-device rendering evidence. **`codegen/` (pipeline instrumentation) is out of scope for this report.**
**Method:** adversarial multi-agent review. Seven independent reviewers over disjoint scopes (lua-world, lua-player, sh-deploy, sh-gates, py-tools, design, viz); **every finding was then handed to an independent verifier instructed to refute it** — re-reading the cited file, checking claims against the engine's own `lua_api.md`, reproducing failures where possible, and checking `docs/decisions.md` so recorded, deliberate tradeoffs are not re-reported as bugs. A completeness critic then searched for what the reviewers missed; its most serious claims were re-verified by hand.
**Outcome:** 69 findings raised in scope, **1 refuted**, 68 confirmed; after cross-dimension dedup, **65 distinct findings**, plus **6 from the completeness pass** = **71 findings: 9 HIGH · 27 MEDIUM · 35 LOW.** Findings marked *(accepted)* touch a decision recorded in `docs/decisions.md` but add a consequence the decision did not consider.

No fixes were applied **by this review**; the findings below were written open. Phase **v0.9** (issues `H11V-019`…`H11V-025`) closed them, and this document was updated in place: every HIGH and MEDIUM row carries a **Status**, and [Fixes applied](#fixes-applied) records what was actually done where that differs from what was recommended. LOW findings are not tabled; their outcomes are in the same section.

## Executive summary

1. **The documentation drifted much further behind the code than the code drifted behind anything.** Six of nine HIGH findings are spec lines that would actively misdirect the next contributor — starting with `CLAUDE.md` still declaring the repo *"specification-only — no code exists yet"* against 64 commits and a released, device-tested game, and prescribing a video driver (`ogles2`) that makes the device build refuse to start. `docs/decisions.md`, by contrast, matched the code everywhere the reviewers checked.
2. **One real credential-exposure path exists in scope.** The deploy's `sshpass -p` fallback puts the device password into `ps`-visible argv for the whole transfer, and the unquoted expansion silently breaks passwords containing a space.
3. **The gates are mostly sound, and several measure something other than what they claim.** `run_local.sh` crashes on every documented flag; `check_assets.py --pack` audits the retired v0 pack, so the colony delivery of record cannot be gate-audited at all; `check_lua.sh` parses with Lua 5.4 syntax the engine's LuaJIT rejects; the post-launch llvmpipe confirmation in the deploy is dead code.
4. **The visualization layer is in good shape where it was measured, and the audit itself has three unrecorded gaps.** The shipped pack's ladder steps, the melt tint, the scanner extrusion contract and the install pipeline all re-verified exactly. But the §4.1 ladder *order* was inverted by the delivery while three documents claim compliance; two Rule-2 hue collisions and a fourth Rule-5 pair were never audited; and on the live device the engine's touch overlay draws a zoom magnifier and a raw `Aux1` label mid-screen — tapping the magnifier turns the camera instead of zooming.

The one **refuted** finding is worth keeping: a reviewer claimed the worldgen probe races future ABMs; the verifier proved emerged-but-playerless blocks are never *active* in Luanti, so ABMs cannot fire during the gate. The adversarial pass exists for exactly this.

### Where the outcome is not what the review recommended

**M9 — missed by the decomposition, then caught and fixed.** It was the one MEDIUM no v0.9 issue
listed: `git log 4130b54..HEAD -- tools/run_on_pi.sh` was empty, so the file went untouched through
six issues. This document's own Status pass is what found it — the point of recording outcomes rather
than intentions — and `H11V-026` was opened and closed rather than marking a miss as a deferral.

The fix is larger than the finding asked for, for a measured reason. Skipping only the scale dance on
a second launch still starts a second engine, and that newcomer truncates the **running** instance's
`h11v-debug.txt` — so the deploy's renderer check would read a log describing a different run, the
exact failure that truncation's own comment exists to prevent. So the liveness gate sits before the
STATE read, before the truncate, before the game symlink and before `trap restore_scale`: the second
tap is a complete no-op that the first instance cannot feel, with a `swaynag` banner where one is
available and silence where it is not — never a scale change.

**L14 was worse than reported.** The guard compared against forms `swaymsg` never produces, and unity
was therefore *never* recognised: `sway_output()` re-renders the JSON through Python, and sway reports
scale as a double, so a panel at unity arrives as `1.0` and fell through both comparisons. Every
launch on an unscaled panel did a pointless reconfigure round trip. The new guard normalises, so it
holds whichever form is real.

**M15 — deferred as recommended, with the limitation moved into the code.** `1f228aa` did not fix the
alpha-blind seam metric. It wrote the fact into `edge_report` itself, so the next reader learns there
that the diff is RGB-only and therefore near-vacuous on `h11_bloom` — at the point where they would
otherwise trust the number. **Home: the next art re-delivery**, which is when a changed `h11_bloom`
would make it matter.

**M19 — deferred as recommended; ARCHITECTURE states the constraint, not the design.** `023bc4c`
added §*How a plan arrives is not decided yet*: the two candidate shapes (a `build` intent carrying a
plan reference, or a second endpoint with its own wake condition and budget), the rule that the
`Intent` schema may not silently grow, and the `docs/decisions.md` line required either way. Nothing
was implemented; the second seam still has no transport. **Home: v3.1**, where it is now named debt.

**M20 — recorded as a design constraint, not implemented.** `023bc4c` added §*The anchor is an input
to the frontier*: the frontier's inputs become `(pos, cycle, seed, anchors)`, anchors being a
persistent ordered log of placements and removals, and `shielded` takes the cycle so an anchor planted
at cycle 12 does not un-infect what cycle 5 already took. A wall, not an undo. That resolves the
contradiction on paper; nothing computes it. **Home: v4**, where the anchor is built.

**M22 — the audit was corrected; the art was not.** `9e08c97` re-measured every pair rather than
adding the two rows the finding asked for, and the framing changed with the numbers. A pair inside
8 L\* is where Rule 2 *starts applying*; the failures are those also inside 60° of hue, and there are
**seven** — but not the seven §11 first listed: two of those (`lithic`↔`bloom` at Δhue 106°,
`lithic`↔`beacon` at 154°) clear the hue requirement outright and were never failures, and two real
failures were absent from the count. `prefab ↔ regolith_side` is recorded **OPEN for the next
re-delivery**, not fixed: it has none of the escapes the other pairs have — not two faces of one
block, not a light source, not required by the brief, and no chroma to lean on — and it is the
built-against-terrace boundary, the most common thing a player will build. The lever is measured and
written down (lift `prefab` 2.9 L\*, which restores every gap) and both hue levers are recorded as
blocked. Re-drawing a delivered texture is a delivery, not an edit, so the fix waits for one.

**M23 — accepted with its reason, and the review's own proposed fix refused on measurement.** The
fourth Rule-5 pair is real: `nodes.lua` wires `h11_lithic_top` as bedrock's top face, at +2.9 L\*.
The review proposed brightening it by ~5 L\*. `9e08c97` measured that: +5 would put `lithic_top`
0.5 L\* from `fines`, trading one thin top/side step for two live Rule-2 failures inside a column the
player digs straight through. §11 now reads *"4 of 4 pass the arithmetic, one of them by 2.9"* and
states the acceptance with its reason, which is the honest form of this finding.

**M25 — partially fixed. The property is set; the button is still drawn.** `0a145ef` sets the
`zoom_fov = 0` object property on join, which silences what the magnifier *does* — with no zoom FOV
for the client to apply there is nothing to predict and nothing to correct, which is the FOV flash
turning on L used to cause. Not yet re-measured on the panel (the device was in use), so `turn.lua`'s
`set_fov` pin stays as the belt. It does **not** remove the button, and the review's claim that it would was wrong: 5.10 draws the
magnifier and the raw `Aux1` label unconditionally, whatever the player is able to do, and the taps
those zones eat still arrive in `turn.lua` as a turn. Recorded as residue in
`tools/device/gamepad.conf` and `docs/decisions.md` rather than papered over. Removing it needs
5.11's touchscreen layout editor, and the standing decision is to stay on the Debian package.
**Home: 5.11.**

**M2 — enforced rather than declared.** The review offered "enforce in `init.lua` or drop the line";
`0a145ef` did both. `game.conf` no longer declares a floor with a key no engine reads, and `init.lua`
errors before loading anything if `core.features.bulk_lbms` is absent — flagged 5.10.0 in
`lua_api.md`, so the check is exactly the floor the dead line claimed and cannot lock out the device.

**M26 — decided, not backfilled.** No execution reports exist for v0.4–v0.8 and none will be written.
An execution report is worth something because the run wrote it; five reconstructed out of `git log`
would carry the shape of evidence and none of the substance, and the next reader would have no way to
tell them from earned ones. Instead `SDLC.md` gained §*What the record actually is, and what the
harden sweep reads*: what exists per version and how each was shipped, the rule that a full-tree
review at a tag is the code review of record for every earlier version that has none of its own — so
**this document covers v0.4–v0.8**, having read the repository at tag `0.8.0` rather than v0.8's
diff — and the rule that `specification/implementation/*code-review*.md` is the only input the
phase-boundary sweep has. A finding recorded anywhere else is a note, not a work item.

### Architecture impact

The changes below alter documented behaviour or a contract, and are the ones the next phase's
RECONCILE step needs before it decomposes anything.

**1. The node-id contract is code now, and `check_assets.py` runs for every issue.** `eee6c7f` made
`check_assets.py` parse the node ids out of `ARCHITECTURE.md` §Components and out of `nodes.lua` and
report a finding in either direction. That turned an art check into a doc-and-code contract, so the
gate was promoted from *"whenever art changed"* to one of the three that run for **every issue** —
measured at 1.02 s, and four of the five pipeline skills already ran it unconditionally.
`SDLC.md` §The acceptance gates records the promotion. The coupling it is bought with: inside §Components'
**grown** and **built** bullets, nothing is in backticks except a node id. Rename the heading or the
bullets and the parser goes **red**, not blind.

**2. §4.1 Rule 1's ladder order is amended** (`9e08c97`), from the prescribed
`drift > lithic > regolith > hull > prefab > fines` to the shipped
`hull > drift > regolith > prefab > fines > lithic`, with the reasoning rewritten to argue for the
shipped order rather than to certify the old one. Rule 1 sits under a heading that says *this part is
binding*, and a v1.1 biome author places new materials on those L\* bands — so this is a contract
change, not a note. §11 now says the steps hold and the order was deliberately changed, instead of
"Rule 1 holds at every step". Recorded in the same pass: **Rule 6 is unpassable as written** — at 30%
brightness white reaches only L\* 32.5, so there is room above dimmed bedrock for three rungs of
8 L\*, not six. Worth knowing *before* v1.1 designs a biome against it.

**3. Two new ARCHITECTURE subsections** (`023bc4c`), both constraining work that has not started:
§*How a plan arrives is not decided yet* (the second model seam's transport — see M19) and §*The
anchor is an input to the frontier* (see M20). The second one matters most: it changes the purity
claim the rest of §Mutation is an infection rests on, from `(pos, cycle, seed)` to
`(pos, cycle, seed, anchors)`. Read it before writing v1.2.

**4. Two new roadmap phases** (`023bc4c`). **v1.1** absorbs the world-size debt `docs/decisions.md`
has owed v1 since v0.7: `mapgen_limit` generates only whole mapchunks, so "exactly 128×128" is not
available and the real choices are **80×80 or 240×240** — v1.1 picks one, because biomes need an area
to be distributed across and the frontier needs one to be measured against. **v2.5 — the build
catalogue** gives `h11_build` a phase for the first time (ARCHITECTURE dated it "from v2" in three
places and no v2 phase scheduled it); appended so nothing renumbers, with the three validation caps
in its DoD and *"not one node written"* as the assertion. Alongside them, **v1.2 and v1.4 were
rewritten against the infection design**: the frontier selects targets and the rules table supplies
transformations, v1.2's DoD gains path-independence, and v1.4 asserts node identity **and** that
emerging a long-absent world costs the same order of work — because the replay implementation this
phase forbids would pass the first and fail the second.

**5. The engine floor moved from `game.conf` to `init.lua`** (`0a145ef`) — see M2. A game that will
not load on 5.9 now says so before loading anything, instead of declaring it in a key no engine
reads.

**6. `SDLC.md` names the record and the sweep's input** (`H11V-025`) — see M26. The phase-boundary
harden sweep reads `specification/implementation/*code-review*.md` and nothing else.

`==> removed world 'h11v_dev'`, and execs the engine with `--worldname "$WORLD" --go`. But
`--worldname` only *selects* an existing world; `--world <path>` is the creating form (`--help`:
*"Set world path (implies local game if used with option --go)"*). Reproduced on 5.10 with the
script's own generated config:

```
World 'h11v_dev' not available. Available worlds:
        test    .../worlds/test
        world   .../worlds/world
        planet_A        .../worlds/planet_A
INFO[Main]: Using default world at [.../worlds/world]
```

No `h11v_dev` has ever existed in that directory. So every `run_local.sh` run — the fourth acceptance
gate, the one that runs *whenever anything visible changed* — has been walking around
`worlds/world`, a world nobody named, created at whatever seed and game version it was first
generated under, and `--fresh` has never regenerated anything. The two implementers who hit it found
it independently. **Cost:** one line — `--world "$USER_DIR/worlds/$WORLD"` — plus deciding whether
`--fresh` should still claim success when there was nothing to remove.

**N2 — the documented 16px install path is red, and was red before this phase.** Reproduced end to

$ tools/install_assets.sh --res=16

14/44 file(s), freed 78.9 KiB

*looks* at its own verify step, which is the only reason anyone can see it. The 32px install is green.

reversibility that both `install_assets.sh`'s header (*"switching resolution is one command in either

## Detailed findings

### A. Security & credentials

**H1 — the device password is `ps`-visible during every fallback transfer.** `deploy_to_term35.sh:119` builds `RSYNC_RSH="sshpass -p $DEV_PASS ssh …"`; rsync receives it via `-e` in its own argv, which rsync never masks — so for the whole multi-second transfer, `ps aux` shows the password in clear text (the plain `sshpass -p` uses at lines 100/117 have the same exposure as a startup race). The unquoted expansion also means a password containing a space silently truncates, and the remainder becomes a remote command word — a baffling auth failure. This path runs only when key auth fails *and* sshpass is installed — but line 127 explicitly tells the user to install it. **Fix:** `sshpass -e` in all three paths (password via the `SSHPASS` env var exported only to the child), including `--setup-key`; this also fixes the word-splitting breakage.

### B. Game code (Lua)

**M1 — stock v7 mountains and rivers are still on.** Nothing sets `mgv7_spflags` (engine default: `mountains,ridges,nofloatlands,caverns`); the mountain pass (`mgv7_np_mount_height`: offset 256, scale 112) and ridge river-carving run *independently* of the three pinned noises, so the "one dial" claim in `mapgen.lua` holds only inside the measured window. The world is deliberately unbounded (recorded), so a player walking out — or any seed change — can meet stock mountains above the biome's `y_max=200` rendering as bare lithic, and river canyons beside a comment that says "the pocket world has… not rivers". **Fix:** `core.set_mapgen_setting("mgv7_spflags", "nomountains,noridges,nofloatlands,nocaverns", true)` beside the `mg_flags` override; record the choice.

**M2 — the version pin is inert.** `min_luanti_version` is not among the game.conf keys any engine reads (verified against the full 5.17 bundle; ContentDB's key is spelled `min_minetest_version`). An older engine shows no version message, only the first Lua error. Enforce in `init.lua` via a `core.features` check, or drop the line.

**M3 — spawn on crowns.** `settle()`'s descent stops at the first solid node with two air above — for any column under a spire growth that is the *top of the bloom crown*, so the player spawns standing on the canopy; the keep-descending branch only fires for interior gaps. At density 0.010 with 5×5 crowns, roughly a quarter of candidates are affected; `get_spawn_level` is terrain-only, so the spiral cannot avoid them. Benign (on top, not inside) but the comments describe behaviour the code does not have. **Fix:** skip nodes in groups `leaves`/`tree` during the descent.

**LOW (Lua):** L1 `TREE_DENSITY` unclamped — `≥10` flips the engine into complete-coverage placement, `≤0`/garbage silently deletes all growths *(accepted decision, unconsidered consequence)* · L2 `liquid_range=7` only on the flowing row — split-brain liquid pair · L3 `leafdecay=3` is a minetest_game convention no engine code implements: crowns float forever, the group reads as a promise *(accepted)* · L4 "mandatory" lava/cobble aliases are actually optional-and-deprecated per lua_api · L5 `init.lua` header omits `music`/`turn` from the documented load order · L6 `h11_world.NODES` export comment names a consumer that doesn't exist · L7 `/music` toggles a global flag but stops only the caller; not persisted · L8 a player who rejoins during the pending spawn-emerge is never settled (close over the name, not the ObjectRef) · L9 `set_properties({hp_max=20})` is a no-op with a misleading comment · L10 turn step unclamped — a 2 s server stall spins the camera ~250° (`math.min(dtime, 0.1)`) · L11 FOV pin reads the setting once at load; `set_fov(1, true)` pins to the client's own FOV · L12 `WATER_LEVEL=6` duplicates mapgen's value with no shared constant.

### C. Tooling & gates (shell, Python)

**H2 — `run_local.sh` crashes on every documented flag.** The option loop parses `--profile/--fullscreen/--world/--fresh` but never consumes them; line 94 passes the untouched `"$@"` to `exec "$LUANTI"`, and the engine (verified against the local binary; same parser on 5.10) aborts on any unknown parameter with an option dump that blames the engine. Only the bare invocation works. **Fix:** drop `"$@"` from the exec.

**H3 — the pack-audit mode can only audit the wrong pack.** `PACK = specification/art/h11v` (line 28) while the filename tables were retargeted to colony names and `install_assets.sh` installs from `specification/art/colony`. Running `--pack` today: exit 1 with 17 spurious "missing" findings. Three dimensions found this independently; a re-delivery from the designer can never be gate-audited. **Fix:** repoint `PACK`, the `--pack` help string, the module docstring, and `install_assets.sh`'s line-8 comment.

**M4/M5/M6 — the renderer-verification chain has three gaps that compound.** The deploy's post-launch llvmpipe grep never fires (no repo file sets `debug_log_level`; at the default level `debug.txt` contains no renderer line — the "confirmation" is dead code); the preflight can PASS on EGL evidence alone when `glxinfo` silently produces nothing (Xwayland down, X auth over ssh) — EGL answers V3D about a path the game never takes, the exact recorded lesson; and `measure_device.sh` pipes all deploy output to `/dev/null` during the one run that mints fps numbers. **M7 — the config-swap race has a residual gap after SIGKILL.** The `--stop` path re-probes with pgrep and refuses; the deploy path sends `pkill -9`, sleeps 0.5 s, and swaps unconditionally — on a slow SD card an engine blocked in D-state can complete its config write-back *after* the swap, the exact clobber this block exists to prevent. **M10 — the parse gate speaks the wrong Lua.** `check_lua.sh` probes `luac` first, which is Homebrew's 5.4: `local a = 1 // 2` passes the gate and fails at load inside the engine's LuaJIT (5.1 syntax). Reorder to `luac5.1 luajit …`.
