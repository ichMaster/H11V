# H11V — Full code, design & visualization review (at v0.8.0)

**Date:** 2026-09-14 · **Scope:** the whole repository at tag `0.8.0` (commit `4130b54`) — game Lua, shell tooling, Python gates, `codegen/`, all specification documents, the installed asset pack, and the on-device rendering evidence.
**Method:** 87-agent adversarial review. Eight independent reviewers over disjoint scopes (lua-world, lua-player, sh-deploy, sh-gates, py-tools, design, viz, codegen); **every finding was then handed to an independent verifier instructed to refute it** — re-reading the cited file, checking claims against the engine's own `lua_api.md`, reproducing failures where possible, and checking `docs/decisions.md` so recorded, deliberate tradeoffs are not re-reported as bugs. A completeness critic then searched for what the eight dimensions missed; its four most serious claims were re-verified by hand.
**Outcome:** 78 findings raised, **1 refuted**, 77 confirmed; after cross-dimension dedup, **74 distinct findings**, plus **8 from the completeness pass** = **82 findings: 10 HIGH · 33 MEDIUM · 39 LOW.** Findings marked *(accepted)* touch a decision recorded in `docs/decisions.md` but add a consequence the decision did not consider.

No fixes were applied by this review. Every finding below is open.

---

## Executive summary

1. **The documentation drifted much further behind the code than the code drifted behind anything.** Six of ten HIGH findings are spec lines that would actively misdirect the next contributor — starting with `CLAUDE.md` still declaring the repo *"specification-only — no code exists yet"* against 64 commits and a released, device-tested game, and prescribing a video driver (`ogles2`) that makes the device build refuse to start. `docs/decisions.md`, by contrast, matched the code everywhere the reviewers checked.
2. **Two real credential-exposure paths exist.** The deploy's `sshpass -p` fallback puts the device password into `ps`-visible argv for the whole transfer, and the `codegen` hook records `SSHPASS=<password>` as a "program name" that its own redactor provably does not catch — the exact leak class the project's rule exists to prevent.
3. **The gates are mostly sound, and several measure something other than what they claim.** `run_local.sh` crashes on every documented flag; `check_assets.py --pack` audits the retired v0 pack, so the colony delivery of record cannot be gate-audited at all; `check_lua.sh` parses with Lua 5.4 syntax the engine's LuaJIT rejects; the post-launch llvmpipe confirmation in the deploy is dead code.
4. **The visualization layer is in good shape where it was measured, and the audit itself has three unrecorded gaps.** The shipped pack's ladder steps, the melt tint, the scanner extrusion contract and the install pipeline all re-verified exactly. But the §4.1 ladder *order* was inverted by the delivery while three documents claim compliance; two Rule-2 hue collisions and a fourth Rule-5 pair were never audited; and on the live device the engine's touch overlay draws a zoom magnifier and a raw `Aux1` label mid-screen — tapping the magnifier turns the camera instead of zooming.
5. **`codegen`'s security core holds; its edges leak telemetry.** The real run log contains no secrets (verified over all 583 events), but schema-invalid events are silently dropped (10 `finding.raised` events provably lost on 2026-09-13), and a finished run's log keeps accreting events because the hook is enabled by default — contradicting its own opt-in documentation.

The one **refuted** finding is worth keeping: a reviewer claimed the worldgen probe races future ABMs; the verifier proved emerged-but-playerless blocks are never *active* in Luanti, so ABMs cannot fire during the gate. The adversarial pass exists for exactly this.

## Detailed findings

### A. Security & credentials

**H1 — the device password is `ps`-visible during every fallback transfer.** `deploy_to_term35.sh:119` builds `RSYNC_RSH="sshpass -p $DEV_PASS ssh …"`; rsync receives it via `-e` in its own argv, which rsync never masks — so for the whole multi-second transfer, `ps aux` shows the password in clear text (the plain `sshpass -p` uses at lines 100/117 have the same exposure as a startup race). The unquoted expansion also means a password containing a space silently truncates. This path runs only when key auth fails *and* sshpass is installed — but line 127 explicitly tells the user to install it. **Fix:** `sshpass -e` everywhere (password via the `SSHPASS` env var exported to the child), including `--setup-key`.

**H2 — the codegen hook records `SSHPASS=<password>` as a program name.** Verified end-to-end by the reviewer *and* the verifier: `summarise_bash('SSHPASS=hunter2 sshpass -e ssh …')` returns `program='SSHPASS=hunter2'` because `shlex.split` puts the env-assignment first and `Path(parts[0]).name` takes it verbatim; `redact.py`'s assignment pattern requires a word boundary before `password|token|…`, which fails inside `SSHPASS`, `PGPASSWORD`, even `MY_PASSWORD` (underscore is `\w`). The existing regression test passes only because its secret is `sk-`-shaped. Note the irony: H1's correct fix (`sshpass -e` with an inline env assignment) walks straight into H2 — **fix both together.** In `summarise_bash`, skip leading `NAME=value` tokens; refuse to record any program containing `=`; extend `redact.py`; add `SSHPASS=`/`PGPASSWORD=` regression tests.

**M26 — `redact.py` gaps beyond H2:** `https://user:pass@host/…` URL userinfo, `--password X`, `-p X`, `curl -u user:pass`, and `glpat-…` tokens all pass unchanged (probe-verified); `run.start` records `git remote get-url origin` verbatim. Exposure is local-disk only (`codegen/runs/` is gitignored) and the current remote is SSH — hence MEDIUM, not HIGH.

**M31 — dashboard path traversal.** `paths.run_dir(run_id)` is `runs_root() / run_id` with no validation, and `server.py` feeds it the `run_id` query parameter, so `../../../<dir>` reads files outside the runs root. Mitigated by the `127.0.0.1` bind. Reject run ids that fail `^[A-Za-z0-9_-]+$`.

### B. Game code (Lua)

**M1 — stock v7 mountains and rivers are still on.** Nothing sets `mgv7_spflags` (engine default: `mountains,ridges,nofloatlands,caverns`); the mountain pass (`mgv7_np_mount_height`: offset 256, scale 112) and ridge river-carving run *independently* of the three pinned noises, so the "one dial" claim in `mapgen.lua` holds only inside the measured window. The world is deliberately unbounded (recorded), so a player walking out — or any seed change — can meet stock mountains above the biome's `y_max=200` rendering as bare lithic, and river canyons beside a comment that says "the pocket world has… not rivers". **Fix:** `core.set_mapgen_setting("mgv7_spflags", "nomountains,noridges,nofloatlands,nocaverns", true)` beside the `mg_flags` override; record the choice.

**M2 — the version pin is inert.** `min_luanti_version` is not among the game.conf keys any engine reads (verified against the full 5.17 bundle; ContentDB's key is spelled `min_minetest_version`). An older engine shows no version message, only the first Lua error. Enforce in `init.lua` via a `core.features` check, or drop the line.

**M3 — spawn on crowns.** `settle()`'s descent stops at the first solid node with two air above — for any column under a spire growth that is the *top of the bloom crown*, so the player spawns standing on the canopy; the keep-descending branch only fires for interior gaps. At density 0.010 with 5×5 crowns, roughly a quarter of candidates are affected; `get_spawn_level` is terrain-only, so the spiral cannot avoid them. Benign (on top, not inside) but the comments describe behaviour the code does not have. **Fix:** skip nodes in groups `leaves`/`tree` during the descent.

**LOW (Lua):** L1 `TREE_DENSITY` unclamped — `≥10` flips the engine into complete-coverage placement, `≤0`/garbage silently deletes all growths *(accepted decision, unconsidered consequence)* · L2 `liquid_range=7` only on the flowing row — split-brain liquid pair · L3 `leafdecay=3` is a minetest_game convention no engine code implements: crowns float forever, the group reads as a promise *(accepted)* · L4 "mandatory" lava/cobble aliases are actually optional-and-deprecated per lua_api · L5 `init.lua` header omits `music`/`turn` from the documented load order · L6 `h11_world.NODES` export comment names a consumer that doesn't exist · L7 `/music` toggles a global flag but stops only the caller; not persisted · L8 a player who rejoins during the pending spawn-emerge is never settled (close over the name, not the ObjectRef) · L9 `set_properties({hp_max=20})` is a no-op with a misleading comment · L10 turn step unclamped — a 2 s server stall spins the camera ~250° (`math.min(dtime, 0.1)`) · L11 FOV pin reads the setting once at load; `set_fov(1, true)` pins to the client's own FOV · L12 `WATER_LEVEL=6` duplicates mapgen's value with no shared constant.

### C. Tooling & gates (shell, Python)

**H3 — `run_local.sh` crashes on every documented flag.** The option loop parses `--profile/--fullscreen/--world/--fresh` but never consumes them; line 94 passes the untouched `"$@"` to `exec "$LUANTI"`, and the engine (verified against the local binary; same parser on 5.10) aborts on any unknown parameter with an option dump that blames the engine. Only the bare invocation works. **Fix:** drop `"$@"` from the exec.

**H4 — the pack-audit mode can only audit the wrong pack.** `PACK = specification/art/h11v` (line 28) while the filename tables were retargeted to colony names and `install_assets.sh` installs from `specification/art/colony`. Running `--pack` today: exit 1 with 17 spurious "missing" findings. Three dimensions found this independently; a re-delivery from the designer can never be gate-audited. **Fix:** repoint `PACK`, the `--pack` help string, the module docstring, and `install_assets.sh`'s line-8 comment.

**M4/M5/M6 — the renderer-verification chain has three gaps that compound.** The deploy's post-launch llvmpipe grep never fires (no repo file sets `debug_log_level`; at the default level `debug.txt` contains no renderer line — the "confirmation" is dead code); the preflight can PASS on EGL evidence alone when `glxinfo` silently produces nothing (Xwayland down, X auth over ssh) — EGL answers V3D about a path the game never takes, the exact recorded lesson; and `measure_device.sh` pipes all deploy output to `/dev/null` during the one run that mints fps numbers. Each alone is mitigated; together they mean a GLX regression could produce recorded numbers with no warning printed anywhere. **Fixes:** `debug_log_level = info` + grep the engine log for the actual GPU string; device-mode preflight must *require* the GLX renderer line; capture deploy output during measurement and abort the profile on the warning.

**M7 — the config-swap race has a residual gap after SIGKILL.** The `--stop` path re-probes with pgrep and refuses; the deploy path sends `pkill -9`, sleeps 0.5 s, and swaps unconditionally — on a slow SD card an engine blocked in D-state can complete its config write-back *after* the swap, the exact clobber this block exists to prevent. Mirror the `--stop` logic.

**M10 — the parse gate speaks the wrong Lua.** `check_lua.sh` probes `luac` first, which is Homebrew's 5.4: `local a = 1 // 2` passes the gate and fails at load inside the engine's LuaJIT (5.1 syntax). Reorder to `luac5.1 luajit …`.

**M12 *(accepted, unconsidered consequence)* — the floor re-creates the bug the retheme fixed.** `MIN_TREES=4` sampled columns is an expectation of ~64 growths — 3.2× the DoD's 20 — and the next legibility-driven density drop (0.005 ≈ 80 growths, DoD-legal) sits one wobble-column from red. The recorded purpose ("catches a schematic that places nothing") is fully served by `MIN_TREES=1`.

**M13 — the worldgen gate cannot run on the device platform.** `mktemp -d -t h11v-worldgen` is BSD-only; GNU mktemp refuses, `WORK` becomes empty under `set -uo` (no `-e`), and the run collapses into permission errors on `/world`. Same Mac-ism at `deploy_to_term35.sh:177` (L17). Portable form: `mktemp -d "${TMPDIR:-/tmp}/h11v-worldgen.XXXXXX"`.

**M11, M14–M16:** `install_assets.sh --res=16` exits 0 even when the downscaler dies (and `downscale_pack.py` returns 0 on per-file exceptions), because the resolution-detecting verifier legitimately accepts 32 px; `ln -sfn` drops the symlink *inside* a pre-existing real directory (reproduced on this macOS), so `run_local` can silently run a stale copy while `--gameid list` passes; the seam metric compares RGB only — on `h11_bloom` (47% transparent, black under the alpha) the threshold self-inflates to 106.8 vs a measured wrap of 5.8, so its one tiling check is near-vacuous; and a flattened RGB re-export of any "binary" texture passes every check (reproduced with a synthetic file) — the bloom crown would render as solid cubes with a green gate.

**LOW (tools):** L13 `--stop`'s post-KILL probe checks `luanti` but not `minetest` · L14 unit-scale guard string-compares formats sway never emits → redundant reconfigure each launch · L15 clean runs print a mangled error-count line · L16 `measure_device` skips the credential trimming its siblings do · L17 `mktemp -t` BSD-ism in deploy · L18 the free-port probe binds TCP for a UDP port · L19 Ctrl-C runs cleanup twice and prints a misleading FAIL · L20 `assert_min` lets `3-` print ok (status-2 branch) · L21 `--timeout=3m` disables the hang guard entirely · L22 `detect_node_scale` accepts any divisor of 32 — an 8 px tree validates green *(accepted)* · L23 the Lua cross-check regex misses `"a.png^b.png"` composites — v1's planned glyph-overlay pattern · L24 check_assets claims downscale shares its exemption reasoning; it's a separate name list · L25 both PNG decoders treat unknown filter bytes as filter 0 and skip CRCs — corrupt files get classified, not rejected · L26 one malformed PNG aborts the whole `strip_png_metadata` pass.

### E. Visualization

**H10 — the ladder order inverted, and three documents certify the opposite.** §4.1 Rule 1 prescribes (top→bottom) *drift > lithic > regolith > hull > prefab > fines* "so the cliffs and dunes read brighter against the ground". The shipped pack measures **hull 86.8 > drift 77.9 > regolith 69.7 > prefab 58.7 > fines 50.4 > lithic 42.0** (independently re-measured by the verifier to 0.1 L\*) — lithic went from second-brightest to darkest, hull to brightest. The *steps* all hold (≥8), which is what §11 checked; the *order* — the part Rule 1 says is chosen deliberately — silently flipped, yet §11 says Rule 1 "holds at every step", ROADMAP v0.8's DoD claims full §4.1 compliance, and `nodes.lua:49` cites §4.1 for lithic being "the darkest rung" — citing the spec for the opposite of what it prescribes. The shipped order is defensible (dark bedrock walls, bright hull); the problem is that a v1.1 biome author following the binding rule will place new materials on wrong L\* bands. **Fix:** amend Rule 1 to the shipped order (or record the deviation in §11 + decisions.md) and correct "holds at every step" to "steps hold; order deliberately changed".

**M22 — two unaudited Rule-2 collisions.** `regolith_side ↔ prefab`: ΔL\* 5.1, ΔH 50°, ΔC only 5.3 — both muted blue-greys with *no chroma lever*, unlike all seven audited pairs (ΔC 26–51). This is the built-against-terrace boundary — the single most common build placement — and at 30% brightness (Rule 6, which §11 never reports) they sit at L\* 17 vs 15 with C\* ≈ 2–4. `lithic_top ↔ fines`: ΔL\* 5.5, ΔH 41°, ΔC 8.3. Neither appears in §11's "seven formal collisions, each checked rather than counted".
