# v0.9 — GitHub Issues

Issues for phase **v0.9 — The review pass** (version **v0 — The device: one player, one island, at a
measured frame rate**), derived from the per-phase Tasks in [ROADMAP.md](../ROADMAP.md) (§v0.9) and
the verified findings in [v0.8-code-review.md](v0.8-code-review.md). This file is scoped to a single
phase; IDs continue from the previous phase (H11V-018 → **H11V-019…H11V-025**).

The phase closes a 7-dimension adversarial review of tag `0.8.0`: 71 verified findings, 9 HIGH, 27
MEDIUM, 35 LOW, `codegen/` excluded. Its shape follows the review's own finding — the code survived
adversarial reading almost untouched, while **six of nine HIGHs are specification lines that would
misdirect the next contributor**. Doing this before v1 is the point: `generate-issues` decomposes
those same documents, so a v1 generated today would inherit `ARCHITECTURE`'s pre-retheme node list and
a `ROADMAP` that still replays mutation cycles the architecture settles are never replayed.

**Reconciliation note (Step 0.5).** The code is ground truth at v0.8: 13 nodes in two halves, six
modules loaded by `init.lua`, the colony pack installed at 32×32 from `specification/art/colony/`.
`ARCHITECTURE.md` is stale against all three and is corrected inside H11V-022 rather than assumed. No
execution report exists for v0.4–v0.8 (review M26), so the review document itself is the record this
phase reconciles against; H11V-025 addresses that gap.

### H11V-019 — Gate repairs: every gate must measure what it claims

**Description:**
Eight review findings, all of the same kind: a gate that lies or dies. Two are HIGH — `run_local.sh`
crashes on every documented invocation, and the pack-audit mode audits the retired v0 pack so the
colony delivery of record cannot be gate-checked at all. Touches `tools/`.

**What needs to be done:**
- **H2** — `run_local.sh` parses `--profile/--fullscreen/--world/--fresh` and then passes the
  untouched `"$@"` to `exec "$LUANTI"`, which aborts with *Unknown command-line parameter* and an
  option dump that blames the engine. Drop the passthrough; comment so it is not reinstated.
- **M14** — `ln -sfn` cannot replace a pre-existing real directory: it drops the symlink *inside* it,
  exits 0, and `--gameid list` still passes because the stale copy is a valid game named `h11v`. Detect
  and die with a message naming the stale directory.
- **H3** — `check_assets.py`'s `PACK` points at `specification/art/h11v`; the tables are colony names
  and `install_assets.sh` installs from `specification/art/colony`. Repoint it, and fix the `--pack`
  help string, the module docstring (still citing `ART.md`) and `install_assets.sh`'s stale comment.
- **M16** — the alpha-regime classifier is bypassed by a colour-type-2 re-export: `alphas()` returns
  `{255}` for RGB and `{255} ⊆ {0,255}`, so a flattened `h11_bloom` or `crosshair` passes as "binary"
  and ships opaque. Require both values present, or reject colour-type-2 for binary/partial entries;
  `tRNS` is never read either.
- **M10** — `check_lua.sh` probes `luac` first, which is Lua 5.4 here; the engine embeds LuaJIT (5.1),
  so `1 // 2` passes this gate and fails at load. Prefer 5.1-compatible checkers and report which one
  was used. The `luajit -bl -o /dev/null` branch is unverified — fix or label it.
- **M11** — `install_assets.sh` checks neither pipeline's status under `set -uo` without `-e`, so a
  `--res=16` request whose downscale step dies exits 0 with a 32 px tree (the verifier legitimately
  accepts 32). Check both.
- **M12** *(recorded decision, unconsidered consequence)* — `MIN_TREES=4` encodes ~64 growths, 3.2× the
  DoD, and `MIN_GROWTHS=20` already binds at 2. Set `MIN_TREES=1` and note the 16-granularity.
- **M13, L18–L21** — `mktemp -d -t` is BSD-only and kills the gate on the Pi; the free-port probe binds
  TCP for a UDP port; the `INT` trap resumes the script and prints a misleading FAIL; `assert_min`
  lets `3-` print ok; `--timeout=3m` silently disables the hang guard.
- **L22–L26** — resolution detection accepts any divisor of 32; the Lua cross-check regex misses
  `"a.png^b.png"` composites (v1's planned glyph overlay); the shared-exemption comment is false;
  both PNG decoders treat unknown filter bytes as filter 0 and skip CRCs; one malformed PNG aborts
  the whole strip pass. **M15 stays deferred** — leave a comment at `edge_report` naming the
  alpha-blindness rather than implementing an alpha-aware metric.

**Dependencies:** None

**Expected result:**
Every documented invocation of every gate runs, and each gate's green means what its own documentation
says it means.

**Acceptance criteria:**
- [ ] `tools/run_local.sh --profile=low --world=x --fresh` starts the engine instead of aborting
- [ ] `tools/check_assets.py --pack` audits the colony delivery (caBX warnings tolerated in pack mode)
- [ ] **Gate:** a flattened RGB re-export of a binary-alpha texture is rejected by `check_assets.py`;

- [ ] **Gate:** `tools/check_lua.sh` reports which checker it used; `tools/test_worldgen.sh` PASS
- [ ] `bash -n` clean on every edited script; `mktemp` forms are portable

### H11V-020 — The device password must never reach a process table

**Description:**
The one finding in this review with a security dimension, plus the deploy's two silent-failure paths.
Touches `tools/`.

**What needs to be done:**
- **H1** — `RSYNC_RSH="sshpass -p $DEV_PASS ssh …"` is passed to rsync via `-e`, and rsync never masks
  its own argv: `ps aux` shows the device password in clear text for the whole multi-second transfer.
  The bare `sshpass -p` uses and `--setup-key` share the exposure as a startup race, and the unquoted
  expansion truncates any password containing a space. Move every call to `sshpass -e` with `SSHPASS`
  exported to the child only. Grep the finished file to prove no `sshpass -p` and no `$DEV_PASS`
  interpolation into a command string remains, and never echo or log the assignment.
- **M4** — the post-launch llvmpipe confirmation is dead code: nothing sets `debug_log_level`, so the
  engine log holds no renderer line and the grep silently skips while the comment above it promises
  the renderer actually used has been confirmed. Add `debug_log_level = info` to
  `tools/device/minetest.conf`, grep the engine's own log for the GPU string, and print a loud NOTE
  when there is no evidence rather than skipping.
- **M7** — the deploy sends `pkill -9`, sleeps 0.5 s, and swaps the config unconditionally; an engine
  blocked in D-state on a slow SD card can finish its config write-back after the swap — the exact
  clobber the block exists to prevent. Mirror `--stop`: poll until gone or a deadline, and die without
  swapping if it survives.
- **M5, M8** — `gpu_preflight` can PASS on EGL evidence alone when `glxinfo` silently produces nothing,
  which is the recorded lesson inverted ("a check that verifies the wrong path is not a weaker check,
  it is a false one"). Require the GLX renderer line in device mode, assert direct rendering, surface
  `glxinfo`'s stderr — and rewrite the header and `--help`, which still teach the abandoned EGL-first
  rationale.
- **M6, L15, L16** — `measure_device.sh` discards all deploy output during the one run that mints the
  numbers recorded in `docs/decisions.md`; its clean-run error count prints mangled; its credential
  parsing lacks the trimming and guards its siblings have.
- **L13, L17** — `--stop`'s post-SIGKILL probe checks `luanti` but not `minetest`; `mktemp -t` is a
  BSD-ism.

**Dependencies:** None

**Expected result:**
No path in `tools/` can put the device password where another process can read it, and the renderer
verification chain either produces evidence or says loudly that it did not.

**Acceptance criteria:**
- [ ] `grep -n 'sshpass -p' tools/` returns nothing; `$DEV_PASS` appears in no command string
- [ ] The deploy refuses to swap the config when the engine survives the SIGKILL escalation
- [ ] `gpu_preflight.sh` in device mode fails when the GLX probe yields nothing; `--help` matches the code
- [ ] **Gate:** `bash -n` clean on every edited script. *Device deploy is NOT run in this issue — the
      device is in use; the deploy paths are verified statically and exercised in the phase's device
      pass.*

### H11V-021 — Game code: terrain honesty, spawn, and the overlay that turns the camera

**Description:**
Four MEDIUMs and the Lua LOWs. One changes the terrain, so the worldgen gate's numbers are re-recorded
against the new world rather than the thresholds re-tuned. Touches `games/h11v/`.

**What needs to be done:**
- **M1** — `mgv7_spflags` is never set, so v7's default `mountains,ridges` passes still run,
  independent of the three noise params `mapgen.lua` pins: the "Height is then simply terrain_base"
  claim and the "lakes and a sea, not rivers" comment are both false outside the measured window, and
  the world is deliberately unbounded. Pin the flags (verify the names against the bundled
  `minetest.conf.example`) and explain why the pinned noises do not govern these passes.
- **M3** — `settle()`'s descent stops at the first solid node with two air above, which under a spire
  growth is the *top of the bloom crown*; the keep-descending branch can never fire for a crown top,
  so roughly a quarter of spawn candidates put the player on the canopy. Descend through `leaves`/`tree`
  groups and correct the comments that describe behaviour the code does not have.
- **M25** — `creative_mode` gives every player the default `zoom_fov` object property, so the touch
  overlay draws a **zoom magnifier and a raw `Aux1` label over the right third of the playfield** —
  and because `gamepad.conf` binds both controls as turn transports, tapping the magnifier *turns the
  camera left*. Set `zoom_fov = 0` as a player property on join; report whether 5.10 offers any way to
  suppress the aux1 overlay.
- **M24** — `gamepad.conf` documents `zoom_fov = fov` as the zoom neutraliser; `docs/decisions.md`
  records the measured opposite and `zoom_fov` is a player property, not a conf key, so the line is
  inert. A contributor trusting it would delete `turn.lua`'s pin as redundant.
- **M2** — `min_luanti_version` is not a key any engine reads; the compatibility floor is silently
  unenforced. Remove or demote it, and enforce the real floor in `init.lua` if it can be done cheaply.
- **Lua LOWs** — L1 unclamped `TREE_DENSITY` (≥10 flips the engine into complete-coverage placement);
  L2 split-brain `liquid_range`; L3 inert `leafdecay`; L4 the "mandatory" alias comment lua_api marks
  optional-and-deprecated; L5 `init.lua`'s documented order omits two of five modules; L6 an export
  comment naming a consumer that does not exist; L7 `/music` global-or-per-player; L8 a rejoining
  player never settled; L9 a no-op `hp_max`; L10 unclamped turn step; L11 a stale FOV pin;
  L12 a duplicated `WATER_LEVEL`; L31 "one step" where it is two.

**Dependencies:** H11V-019 (the worldgen gate must be trustworthy before terrain moves)

**Expected result:**
The world behaves as its own comments describe, and nothing the engine draws over the playfield does
something other than what it depicts.

**Acceptance criteria:**
- [ ] **Gate:** `tools/check_lua.sh` green; `tools/test_worldgen.sh` PASS with the post-`spflags`

- [ ] `zoom_fov` is set from the server on join; the reasoning is in a comment

## v0.9 scope notes

**Total effort:** roughly 15–20 days of nominal size, dominated by H11V-019 and H11V-022; in practice
most of it is small, mechanical and independently verifiable, which is why the phase is decomposed by
*file ownership* rather than by severity — six of seven issues touch disjoint files and can run
concurrently.

**Critical path:** H11V-019 → H11V-021 → H11V-025, with H11V-022 → H11V-023 running alongside.

**Phase DoD (roadmap §v0.9):** every HIGH and MEDIUM in the review's table is either fixed or
explicitly re-classified as deferred **in that document**, with the reason; the review document carries
a Status per finding; all five acceptance gates green; `check_assets.py --pack` audits the colony
delivery; no specification document contradicts the shipped code on a load-bearing detail.

**Contracts pinned this phase:** the node catalogue description in `ARCHITECTURE` §Components against
`nodes.lua`'s registered ids (H11V-022); the count of protected model seams (H11V-023); §4.1's binding
separation rules against the shipped pack (H11V-024).

**Device note:** the device is in use during this phase, so **no issue runs a device deploy**. Every
deploy-path change in H11V-020 is verified statically (`bash -n`, grep proofs, reading), and the phase
closes with a single device pass before release rather than per-issue device runs. A frame-rate budget
is never estimated on the Mac and never accepted from a software rasterizer; **no paid APIs** anywhere
in the acceptance path.

**Out of scope, deliberately:** `codegen/` findings (excluded from the review at the user's
direction); **M15**, the alpha-blind seam metric, deferred to the next art re-delivery; the
visualization LOWs that need a device experiment session (L27 crosshair contrast, L28 clouds, L29 fog)
— these are recorded in the review document as deferred with their homes.
